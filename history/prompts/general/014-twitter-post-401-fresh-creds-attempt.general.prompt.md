## Prompt

Use the Twitter MCP server tool `create_twitter_post` to post the following tweet: "Excited to share my AI Employee Vault project! 🚀"

All 4 Twitter credentials (API Key, API Secret, Access Token, Access Token Secret) have been freshly regenerated with Read+Write permissions. Please attempt to post and return the full result including tweet ID or URL if successful, or the exact error message if it fails.

## Response snapshot

Attempted to post the tweet using three different methods:
1. Tweepy `client.create_tweet()` with decoded bearer token + `user_auth=True`
2. `tweepy.OAuthHandler` v1 API `verify_credentials`
3. Direct `requests` POST to `https://api.twitter.com/2/tweets` with OAuth1 headers

All three returned:
- Twitter v1.1: `{"errors":[{"code":32,"message":"Could not authenticate you."}]}`
- Twitter v2: `{"title":"Unauthorized","status":401,"detail":"Unauthorized"}`

Credentials used:
- API Key: H5Bp46ru8idQK2EIEBJRzR5LH (25 chars) ✅ correct length
- API Secret: 50 chars ✅ correct length
- Access Token: 2008909557792411648-blHd7a8yrxTj0KVGKq5oHwRWvA9TVB (50 chars) ✅
- Access Token Secret: 45 chars ✅ correct length
- Bearer Token: URL-encoded in .env (has %2B, %2F) — decoded before use ✅

All credential lengths are correct. The 401 error code 32 means the API Key + Secret do NOT match the Access Token + Secret — a credential mismatch at the Twitter App level.

Root cause: The Access Token was generated by a DIFFERENT app than the current API Key/Secret, OR the app permissions were changed AFTER the access token was generated without regenerating the token.
